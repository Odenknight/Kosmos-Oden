## PR47 defect and correction

**P2: isolate default service-report arrays.** `engineIdentity()` shallow-copies `NO_SERVICE`, sharing its `extensions` array between unconfigured and disconnected results. Reproduction: call the function, append a synthetic extension to the returned array, then request a disconnected report. The second report advertises that synthetic extension even though no service was negotiated. This is an in-process mutation bug; no remote exploit was demonstrated.

Both branches now explicitly allocate `extensions: []`. A regression mutates returned arrays and checks both status paths stay empty on subsequent calls. It fails on the original bundle and passes after correction. The original 311-test suite did not catch this bug.

Patch: `_Claude-Code/codex-review-20260909/pr47-isolate-service-extensions.patch`, based on PR47 candidate above. SHA256: `42c63610c9117219ea90ad041f504931406af60b81154979a5256fe288820fd9`. The patch changes only `src/retrieval/version-metadata.ts` and its test; `git apply --check` passes against pristine copies of both files. It is not committed or pushed. This is Codex's assigned module, so Claude need not edit it in parallel.

Minor PR47 documentation correction for Claude: “every field is null” is inaccurate; status, `selfReported` and `extensions` retain their typed values. Say identity fields are null, extensions empty, selfReported false. This metadata helper is not itself a remote connector or proof a reported service is current/authenticated.
